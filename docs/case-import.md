# 사건목록 가져오기 (case-import.html)

> **2026-11-19 신규**: `case-note.html`과는 **별개의 독립 파일**. 내부 시스템에서 URL로 보이는 JSON(사건 목록)을 가져와, 필요한 키만 선별해서 별도 JSON으로 저장하는 1단계 도구. 사건 관리 노트와 사건번호로 매칭해서 불러오는 기능은 **아직 없음**(다음 단계 예정).

## 배경
사용자가 내부망에서 특정 URL을 열면 모든 사건 목록을 담은 JSON이 브라우저에 그대로 보인다고 함. 이 데이터를 사건 관리 노트의 "기본 사건정보"로 쓰고 싶어함. 다만:
- JSON 스키마를 모르는 상태로 범용적으로 동작해야 함 → 코드가 스키마를 미리 가정하지 않고, 가져온 데이터에서 **실제 등장하는 키를 자동으로 찾아** 사용자가 체크박스로 선별하게 함.
- 외부(인터넷)와는 무관, 사용자의 **내부망 시스템** 하나에만 접속하는 것이므로 CLAUDE.md의 "외부 CDN/리소스 금지" 규칙과는 별개. 다만 브라우저가 다른 출처로 `fetch()`할 때 거는 **CORS 정책**은 이 파일이 어떻게 하든 통제할 수 없음 — 대상 시스템이 `Access-Control-Allow-Origin` 헤더를 주지 않으면 fetch 자체는 실패함 (실제로 로컬 테스트 서버로 양쪽 다 확인함: 헤더 있으면 성공, 없으면 실패).

## 사용 흐름
1. **데이터 가져오기** — 세 가지 방법 중 하나
   - `🌐 URL로 가져오기`: 주소 입력 → 가져오기 버튼 → 이 페이지가 그 주소로 직접 `fetch()`. 성공하면 바로 파싱.
   - `🔗 새 탭에서 열기` + `📋 직접 붙여넣기`의 `📋 클립보드에서 붙여넣기`: CORS로 fetch가 막히면, 주소 입력 후 [🔗 새 탭에서 열기]로 직접 열어 그 탭에서 전체 선택(Ctrl+A)·복사(Ctrl+C) 한 다음, 이 페이지로 돌아와 [📋 클립보드에서 붙여넣기]를 누르면 `navigator.clipboard.readText()`로 자동으로 채워져 바로 파싱됨. (북마클릿처럼 별도 설치가 필요 없음. 클립보드 읽기는 CORS/동일 출처 정책과 무관한 별개의 브라우저 권한이라 가능 — 왜 `window.open`/`iframe`으로 내용을 직접 읽어올 수 없는지는 아래 "왜 자동으로 안 되는가" 참고)
   - 수동 붙여넣기: 위 자동 복사가 안 되면 textarea에 직접 Ctrl+V.

### 왜 완전 자동으로는 안 되는가
`fetch()`가 CORS로 막히면 `window.open()`으로 새 탭을 열거나 `<iframe>`으로 불러와도 **내용을 코드로 읽어오는 것 자체가 막힌다** — 이건 CORS가 아니라 더 근본적인 **동일 출처 정책(Same-Origin Policy)**이라서, 어떤 방법을 쓰든(`fetch`/`window.open`/`iframe`) 서로 다른 출처의 콘텐츠를 스크립트로 읽는 건 전부 차단된다. 반면 "클립보드 읽기"는 출처와 무관하게 브라우저가 그 페이지 자체에 부여하는 권한이라, 사용자가 수동으로 복사만 해두면 그 이후 붙여넣기는 자동화할 수 있다. 이게 이 도구가 택한 현실적 한계.

> 참고로 "화면에 텍스트로 통째로 나오는 JSON을 더 편하게 구조화해서 볼 방법"은 **브라우저로 그 페이지를 열어서 보이는 텍스트 자체가 이미 JSON**이고, `fetch`/붙여넣기 어느 경로로 가져오든 `JSON.parse()`로 완전한 구조적 데이터가 됨 — 추가 변환은 필요 없음. 다만 사람이 눈으로 구조를 보기 편하게 트리로 펼쳐보고 싶다면 `json-viewer.html`(같은 저장소의 범용 JSON 뷰어)에 붙여넣으면 됨.

2. **데이터 경로 지정 (선택)**: "데이터 경로" 칸에 `data.myCaseListVo` 처럼 점(.) 구분 경로를 입력하면 그 위치의 배열을 직접 사용(`getArrayAtPath`). 배열 인덱스(`items[0].list`)도 지원. 비워두면 **배열 자동 탐지**(`findCaseArray`)가 객체 트리 전체를 재귀적으로 훑어 "객체로 이루어진 배열"을 전부 찾고, 후보가 여럿이면 가장 긴 것을 자동 선택하며 다른 후보 경로들도 메시지에 보여줌(그걸 보고 "데이터 경로" 칸에 원하는 걸 직접 지정할 수 있음). 지정한 경로에서 못 찾으면 자동 탐지로 전환되고 경고가 뜸.
3. **키 자동 수집** (`discoverKeys`): 처음 500건을 샘플링해서 등장하는 모든 키를 모음. 체크박스 목록으로 보여주고(첫 번째 사건의 값을 미리보기로 같이 표시), 전체 선택/해제 가능. 선택한 키는 `localStorage`(`CASE_IMPORT_SELECTED_KEYS`)에 저장되어 다음에 다시 가져와도 같은 키 이름이 있으면 유지됨.
4. **사건번호로 쓸 키 지정**: 선택한 키 중 하나를 "매칭 키"로 지정(`localStorage`: `CASE_IMPORT_MATCH_KEY`).
5. **미리보기 만들기** → 선택한 키만 담은 `previewRows` 생성.
6. **(선택) 사건별 상세정보 가져오기**: "사건번호로 쓸 키"를 지정해야 나타남. URL 템플릿에 `{값}`을 넣으면(예: `https://.../detail?caseNo={값}`) 각 사건의 매칭 키 값을 그 자리에 넣어 **사건 수만큼 순서대로 fetch**(`fetchAllDetails`, 비동기 순차 처리, 진행 상황 표시). 사건별로 성공/실패를 따로 기록하고, 실패해도 나머지는 계속 진행. 끝나면 상세 응답에서 발견된 키를 체크박스로 보여주고(`discoverDetailKeys`), 선택해서 반영(`applyDetailKeys`)하면 `previewRows`에 합쳐짐 — **기존 키와 이름이 겹치면 `상세_` 접두어**를 붙여 구분. 이 상세 fetch도 각 요청마다 동일하게 CORS 제약을 받음(목록 fetch가 성공했다고 상세 fetch도 보장되는 건 아님 — 같은 서버라도 엔드포인트별로 CORS 설정이 다를 수 있음).
7. **💾 JSON으로 저장**: 그 시점의 `previewRows`(상세정보를 반영했다면 그것까지 포함)를 아래 형식으로 다운로드.

```json
{
  "version": 1,
  "kind": "case-import-list",
  "exportedAt": "2026-11-19 10:00",
  "sourceUrl": "http://...",
  "matchKey": "caseNo",
  "keys": ["caseNo", "name", "charge", "status"],
  "cases": [ { "caseNo": "...", "name": "...", "charge": "...", "status": "...", "상세_name": "...", "범죄사실": "..." }, ... ]
}
```

## 검증한 것 / 안 한 것
- Playwright로 확인: 중첩 객체(2단계 이상)에서 배열 재귀 자동 탐지, 수동 경로 지정 및 지정 실패 시 자동 탐지 전환, 경로 설정 `localStorage` 유지, 최상위 배열 처리, 키 체크박스 선택·저장, 잘못된 JSON 에러 처리, **로컬 테스트 서버로 CORS 허용/미허용 두 경우 모두 fetch 성공·실패 메시지 확인**, **사건별 상세정보 순차 fetch**(일부 성공·일부 실패 섞인 상황에서 진행률·요약·개별 결과 모두 확인, 키 이름 충돌 시 `상세_` 접두어 처리, 다운로드 결과에 반영 확인), 새 탭 열기·클립보드 자동 붙여넣기.
- **검증 안 됨**: 사용자의 실제 내부 시스템 URL·실제 JSON 스키마·실제 상세조회 URL 패턴. 응답이 매우 크거나(수만 건) 상세정보 URL이 매우 많으면(순차 처리라 느릴 수 있음) 실사용 성능은 확인 안 됨.

## 다음 단계 (미구현, 사용자와 재논의 필요)
- 이 도구에서 저장한 JSON을 사건 관리 노트의 사건 목록과 **사건번호로 매칭**해서, 노트 쪽 상세 정보(범죄사실·체크리스트 등)를 가져오거나 두 데이터를 합쳐 보여주는 기능.
- 큰 목록을 받을 때의 페이지네이션/성능 처리(현재는 미리보기 200건 제한만 있고, 저장은 전체 포함). 상세정보 순차 fetch도 사건 수가 아주 많으면 느릴 수 있음(동시 처리 수 제한 등 최적화는 미구현).
