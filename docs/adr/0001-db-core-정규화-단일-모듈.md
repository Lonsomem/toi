# ADR-0001: 데이터 모양(정규화)은 `db-core` 단일 모듈이 전담한다

- 상태: 채택 (2026-11-24)
- 대상: `case-note.html`
- 관련: `docs/case-note.md` 1~3절, 아키텍처 리뷰(2026-11-24, `/improve-codebase-architecture` 후보 1)

## 배경
사건·템플릿 데이터의 "올바른 모양"(기본값 채우기, 구버전 마이그레이션)이 7곳에 흩어져 서로 어긋나 있었다:
`loadDatabase` 패치, `applyRecoveredData`(패치 없음), `normalizeImportedCase/Template`, `importExternalCases`, `createNewCase`, `getInitialSampleCases`, 그리고 화면 그리기 중 `ensure*`/`if (!Array.isArray(...))` 보정.
그 결과 실제 데이터 유실 버그가 생겼다:
- JSON "덮어쓰기" 가져오기가 사용자 사건 상태 설정(`statusOptions`)과 범죄사실 예문(`chargeFactExamples`)을 지움.
- 임시 백업 복구가 마이그레이션을 건너뜀.
- 내장 DB 디코딩 실패 시 조용히 샘플 데이터를 띄우고, 자동 저장이 실제 파일을 샘플로 덮어쓸 수 있음.

## 결정
1. `case-note.html` 안에 **`<script id="db-core">` 블록**을 두고, 데이터 모양에 관한 모든 규칙을 여기에만 둔다.
   - 순수 코드: DOM·`app`·네트워크 접근 없음. 입력을 받아 결과를 돌려줄 뿐.
   - 내용: 정규화(어떤 원본이든 → 정식 DB), 새 사건 생성(`makeCase`), 공유 JSON v1 변환(내보내기/가져오기 병합·덮어쓰기), 인코딩/디코딩과 저장 전 검증.
   - 5개 진입점(최초 로드, 임시 백업 복구, JSON 가져오기, 외부 목록 가져오기, 새 사건)은 전부 이 모듈을 거친다. 화면 코드의 보정(`ensure*`)은 삭제한다.
2. **테스트는 Node 에서** `db-core` 블록 텍스트를 꺼내 실행한다(브라우저 불필요). 앱과 테스트가 같은 코드를 쓴다.
3. **데이터 일관성 규칙**(각각 테스트로 보장):
   - 모르는 속성은 지우지 않고 보존한다.
   - 정규화는 멱등: 두 번 해도 한 번 한 것과 같다.
   - 내보내기 → 덮어쓰기 가져오기 왕복 시 사건·템플릿이 동일하다(상태 설정·예문·관계인 포함).
   - 저장 직전 인코딩 결과를 다시 디코딩해 메모리 데이터와 비교, 다르면 쓰지 않고 오류 표시.
   - 덮어쓰기 가져오기는 파일에 **있는 섹션만** 교체(없는 섹션은 현재 것 유지). 병합 가져오기는 **추가만**(같은 이름의 상태·같은 예문은 건드리지 않음).
4. **손상된 내장 DB는 읽기 전용**으로 연다: 오류 배너 + 저장 중지, 유효한 임시 백업이 있으면 복구 제안. 샘플 데이터는 내장 DB 가 *비어 있을 때만*.
5. **저장 형식은 그대로**: 내장 DB `version:4`, 공유 JSON `version:1`. 새 속성은 선택(optional)만. 구버전 `case-note.html` 이 새 저장본을 계속 열 수 있어야 한다.
6. 오프라인 유지: `db-core` 에 `fetch`/`XMLHttpRequest`/URL 요청이 없음을 테스트로 검사.

## 검토한 대안
- **현 상태 유지(진입점마다 보정)**: 새 필드마다 7곳 수정, 이미 어긋나 데이터 유실 발생 → 기각.
- **별도 `.js` 파일로 분리**: 단일 파일·외부 의존 0 원칙(CLAUDE.md 절대 규칙)과 Quine 자기 저장 구조에 맞지 않음 → 기각.
- **`app` 메서드로 두고 Playwright 로만 테스트**: 테스트가 느리고 브라우저 설치가 필요, 데이터 규칙이 DOM·상태와 섞인 채로 남음 → 기각.
- **저장 형식 버전 올리기(v5)**: 동료·구버전 파일과의 호환이 깨짐. 규칙 강화는 형식 변경 없이 가능 → 기각.

## 결과
- 새 필드 추가 = `db-core` 한 곳 + 테스트. (화면 노출이 필요하면 화면 코드 추가)
- 숨김 필드(사건개요·비고·customFields/Values)의 동작은 이번에 바꾸지 않는다(별도 결정 대상).
- 이 결정을 되돌리려면 5개 진입점을 다시 각자 보정하게 만들어야 하므로 비용이 크다. 재검토 시 위 유실 버그 재발 여부를 먼저 확인할 것.
